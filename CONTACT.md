# Contact form

The Contact me section appears below every playground page. The navigation, home
hero, and footer link to it. A direct email link is also available.

Messages are sent to **davinderpalbrar401@gmail.com** through a standard HTML POST
to FormSubmit. The visitor's `email` field supplies the reply-to address. No Gmail
password, API key, or running FastAPI backend is needed.

## One-time activation

1. Publish these changes to the live site.
2. Open https://contentbravio.com/#contact and submit a short test message.
3. Complete FormSubmit's spam check. Check davinderpalbrar401@gmail.com (including
   spam) for the FormSubmit activation email and click its confirmation link.
4. Submit another test message and confirm it arrives. Reply to it to verify the
   visitor's email address is used.

The form is not ready to receive normal enquiries until activation is complete.
Only the inbox owner can finish this step. Browser checks alone do not confirm
email delivery.

## Submission behavior

- Name, email, and message are required; fields have length limits.
- Native form submission keeps FormSubmit's default reCAPTCHA enabled, followed
  by its confirmation or error page. The website does not show a false success
  message or clear the visitor's input before a submission.
- A hidden honeypot adds spam filtering.
- Form contents are processed by FormSubmit, as disclosed beside the submit
  button. If the service is unavailable, visitors can use the direct email link.
- The contact form remains visible and can submit when JavaScript is disabled.

Service setup and behavior: https://formsubmit.co/ and
https://formsubmit.co/documentation.

### Connect the three pending providers

1. Use the official free-account/form creation flows linked in the lab and set
   the recipient to `davinderpalbrar401@gmail.com`. Verify that address and enable
   submission notification emails in the provider dashboard.
2. Edit `forms-config.js`: set `web3formsAccessKey` to the public form access key,
   `formspreeFormId` to the ID after `https://formspree.io/f/`, and
   `formsparkFormId` to the ID after `https://submit-form.com/`.
3. Publish the change to main. The configured cards are enabled on every device;
   nothing is saved only to an administrator's browser. Blank or invalid IDs
   keep the relevant form disabled. There is no public configuration editor.
4. Send a test through each newly connected service, check the inbox/spam folder,
   and verify reply-to behavior. A configured ID or provider success response
   does not verify inbox delivery. Do not mark a provider as delivery-tested
   without this check.

Only public, client-side submission identifiers belong in `forms-config.js`.
Never commit passwords, account API tokens, private API keys, or CAPTCHA secrets.
Configured IDs must belong to forms using the recipient above. Provider-specific
CAPTCHA options requiring additional client integration need to be wired before
enabling them; native provider-hosted checks remain available where supported.

### Lab behavior

- `form-lab.css`, `forms-config.js` and `form-lab.js` are isolated from the existing
  form and playground. No new libraries or backend are required.
- All lab emails include `test_method`, `test_reference`, and optional `device`.
  The subject includes the method and reference. References are generated by
  JavaScript and are not proof of delivery.
- The instant form only clears after a successful HTTP response AND an explicit
  FormSubmit `success` value. Activation, errors, non-JSON responses, timeouts,
  and uncertain network outcomes preserve the message. No automatic retries.
- Requests in flight disable the instant form to prevent duplicate sends. A
  20-second timeout restores editing and tells the visitor delivery is unknown.
- Native forms show the provider's result page. The site never labels a native
  POST as delivered before that response. The original CAPTCHA is unchanged.
- The attachment test allows one JPG, PNG, or PDF up to 10,000,000 bytes. Browser
  validation supplements the provider's limits; server validation remains the
  provider's responsibility. Honeypots are included.
- The email-app form opens a draft and explicitly requires sending in the mail
  app. It does not claim that opening the draft sent a message.
- With JavaScript disabled, the original contact form and native attachment test
  remain available; the direct email link also works. Other lab forms are disabled.
- Personal form contents are not saved in localStorage or sent to multiple
  providers. Only the selected provider receives a submission.
